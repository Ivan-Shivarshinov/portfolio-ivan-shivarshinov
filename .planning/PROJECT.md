# Portfolio: Иван Шиваршинов

## What This Is

Персональный портфолио-сайт веб-разработчика с продуктовым подходом (Product-minded Web Developer). Статический сайт на Astro (static SSG + islands) с разделами Work (интерактивный индекс проектов на Three.js — центральная механика сайта), Lab (эксперименты, AI-инструменты, прототипы) и About (история практики, способ работы, формат сотрудничества). Разрабатывается по гибридной модели «Astro + AI-агент + Stacki + Git»: единый источник истины — файлы Astro-проекта в Git; Stacki — визуальная рабочая поверхность над тем же кодом; AI-агент — программная рабочая поверхность.

## Core Value

Портфолио должно подтверждать позиционирование «веб-разработчик с продуктовым подходом»: центральная интерактивная механика (индекс работ) — осмысленное доказательство компетенции, а не декоративный 3D-эффект; сайт превращает посетителя в заявку. Контрольный вопрос: «Помогает ли конкретное решение лучше понять работу, почувствовать качество или перейти к следующему шагу? Если нет — оно не обязано присутствовать на сайте».

### Out of Scope

- Webflow как платформа портфолио — платформа зафиксирована: Astro; Webflow остаётся компетенцией и контекстом позиционирования
- Постоянная WebGL-сцена на каждой странице — бюджет интерактивности: одна центральная механика + один выразительный переход
- Несколько одновременно работающих shader-эффектов — запрещено Three.js brief
- Навигация и критический контент внутри WebGL — HTML остаётся главным уровнем интерфейса
- Абстрактный blob/сфера в hero без связи с работами — запрещено Three.js brief
- Производственная реализация в одном HTML-файле — допустима только изолированная песочница прототипа
- Тяжёлый клиентский framework для всего сайта, внешняя CMS, БД, глобальный state manager, сложный backend — запрещено ADR (baseline стека)
- Полноэкранная 3D-галерея, в которой трудно найти кейс — противоречит центральной механике
- Сетка логотипов технологий как главный визуальный аргумент — ослабляет образ (REQ-design-implications)
- Неоновая AI-эстетика / бесконечные градиенты как главный визуальный язык — ослабляет образ (REQ-design-implications)
- Кинематографическая preload-заставка — необязательно для запуска (design SPEC)
- Полное повторение desktop-анимации на мобильных — мобильная версия не обязана повторять desktop 1:1
- Большое количество анимационных библиотек — порядок выбора: CSS → vanilla JS → View Transitions → island; GSAP/FLIP допустим только для центрального перехода

## Constraints

Сгруппированы по источникам; полный текст: `.planning/intel/constraints.md`.

Из `design_direction` (SPEC, precedence 0):
- **[nfr] Концепция**: «Calm Interface, Active Work»; 6 принципов: ясность, контраст состояний, интерактивность по смыслу, техническая достоверность, личный масштаб, рост без ребрендинга
- **[schema] Визуальный язык**: нейтральная светлая основа, графитовый текст, один акцент; grotesk + моноширинный (индексы, роли, даты, статусы); строгая модульная сетка с крупными полями; крупные реальные интерфейсы и схемы вместо мокапов; прямоугольные плоскости, тонкие линии, номера и подписи
- **[schema] UX/IA**: HOME → Hero → Selected Work → Capabilities → Featured Case → How I Work → Lab Preview → About → Contact; WORK — индекс с фильтрацией/метаданными; CASE STUDY — проблема → контекст → ответственность → решения → артефакты → результат → развитие; LAB, ABOUT, CONTACT; работы доступны почти из любого состояния
- **[protocol] Центральная механика**: desktop — hover активирует крупное превью, строка раскрывает роль/тип задачи/один сильный факт, очень умеренная реакция на курсор, переход в кейс продолжает состояние; mobile — превью встроены или раскрываются по тапу, крупные tap targets, без hover-условий доступа
- **[protocol] Motion по зонам**: навигация — плавная смена состояния; hero — лёгкая реакция без обязательного 3D; index — hover-preview + follow-cursor с малой амплитудой; scroll — reveal группами; case transition — shared-element; Lab — свободные экспериментальные механики; reduced-motion — полноценное статичное состояние
- **[protocol] Референсы**: каркас Jakub Jakubik + структура Coronel + индекс Anna Parellada + UI-система Prime UI + логика кейсов Desses + 10–20% выразительности Trionn и Content Architecture
- **[nfr] Реализуемость v1**: реалистично: системная сетка, индекс с hover-preview, GSAP/FLIP-переходы, scroll reveal, CMS-структура Work/Lab, ASCII/technical labels, reduced-motion; необязательно: постоянная WebGL-сцена, сложные шейдеры, preload-заставка, повторение desktop-анимации на mobile
- **[nfr] Технические критерии**: не жертвовать LCP/INP; клавиатура, видимый focus, контраст, reduced motion; переиспользуемые компоненты, tokens, ограниченный набор анимационных паттернов; content-first; mobile-first checks
- **[nfr] Границы**: не шаблонная сетка карточек, не имитация award-студии, не терминал разработчика, не геймерский AI-сайт, не анимация без понимания роли/услуг, не стерильный минимализм

Из `threejs brief` (SPEC, precedence 1):
- **[protocol] Роль Three.js**: усиливает историю, не становится историей; основное применение — индекс Work; вторичное — Lab-эксперимент; допустимое — переход Build → Improve → Extend; сам факт 3D ценности не создаёт
- **[protocol] Не рекомендуется**: blob/сфера в hero без связи с работами, постоянно движущийся фон, полноэкранная 3D-галерея, разделение на три равноправные услуги, несколько shader-эффектов, droplets/cloth/частицы ради демонстрации, навигация внутри WebGL, тяжёлая сцена на каждой странице
- **[schema] Архитектура**: ProjectIndex.astro → ProjectIndexContent.astro (HTML, семантика, ссылки, данные) + ProjectScene + project-scene/{createScene, materials, transitions, assets, dispose} + ProjectFallback.astro; данные Work из Content Collections без дублирования; совместимость со Stacki; жизненный цикл: lazy init, pause вне viewport и в неактивной вкладке, resize без накопления listeners, освобождение геометрии/материалов/текстур, ограничение DPR, один render loop, совместимость с View Transitions
- **[nfr] Производительность/доступность**: первый экран и список читаются до загрузки сцены; canvas не блокирует LCP; мобильный — осознанно упрощённый вариант, а не уменьшенный desktop; reduced-motion отключает сложное движение; no-WebGL — полноценный интерфейс; клавиатурный фокус вызывает эквивалентное состояние сцены; слой не перехватывает скролл; изображения через Astro pipeline
- **[nfr] Бюджеты прототипа**: одна сцена на страницу, один render loop, минимум прозрачных полноэкранных слоёв, ограниченный DPR, без фонового 1080p-видео, максимум одна главная scroll/selection-анимация, статичный fallback одновременно с desktop-прототипом
- **[protocol] Процесс**: 6 этапов: формулировка задачи одним предложением → пакет референсов (3–5) → изолированный прототип → визуальная проверка рядом с реальной типографикой → production-интеграция (отдельный понятный коммит) → полировка только после устойчивой интеграции; порядок: keyframe → motion → оптимизация и fallback
- **[protocol] Правила AI-агента**: агент исследует, объясняет архитектуру, собирает прототипы, реализует, анализирует diff, оптимизирует, проверяет fallback; не определяет позиционирование, структуру Work/Lab/About, финальную метафору, количество эффектов, визуальную иерархию; шаблон постановки задачи зафиксирован в brief
- **[nfr] Критерии принятия**: позиционирование усилено; calm в покое; типографика и HTML-иерархия важнее canvas; сцена связана с кейсами; изолированный слой в Astro; контент не дублируется; правки через Stacki не требуют переписывания; работает без WebGL; mobile + reduced-motion; ресурсы корректно освобождаются; каждый эффект имеет обоснование
- **[nfr] Первый milestone**: desktop-прототип индекса Work: реальная типографика, 3 тестовых проекта, одна сцена, 3 состояния, переключение по hover и keyboard focus, один спокойный переход, статичный fallback, reduced-motion, схема архитектуры, список ассетов с весом, вывод о поддержке дизайн-направления; НЕ входят: фоновые видео, сложные шейдеры, тяжёлые 3D-модели, мобильная WebGL-сцена, финальная интеграция всех кейсов, эффекты вне индекса
- **[protocol] Решение после прототипа**: Integrate / Move to Lab / Discard; отказ от прототипа не считается неудачей — его задача проверить гипотезу до дорогой архитектурной зависимости
