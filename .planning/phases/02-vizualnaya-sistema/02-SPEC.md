# Phase 2: Визуальная система — Specification

**Created:** 2026-08-02
**Ambiguity score:** 0.12 (gate: ≤ 0.20)
**Requirements:** 9 locked

## Goal

Единая визуальная система «Calm Interface, Active Work» реализована в коде: tokens.css расширен (bp-токены, шаги шкалы, easing-набор) без переименования ролей, все 5 страниц используют оболочку системы (контейнер, типографика, nav, структурный footer), переиспользуемые компоненты принимают семантические пропы, интерактивные состояния реализованы только CSS в рамках бюджета motion; концепты первого экрана (2–3 варианта) генерируются в Figma через MCP как референс-выбор для главной.

## Background

Фаза 1 завершена и верифицирована (39/39 must-haves, 5/5 SC). Текущее состояние кода:

- `src/styles/tokens.css` — единственный файл токенов, 5 групп: 7 цветов, 3 шрифта + 4 текстовые роли (body 16 / label 14 / heading 20 / display 32), 7 отступов, 3 контейнера, 4 motion (150/250/400ms + 1 easing). Значения — baseline, UI-SPEC 01 разрешает уточнять значения и добавлять токены, но не переименовывать роли.
- `src/layouts/BaseLayout.astro` — nav из 5 меток без стилизации, пустой `<footer>`, scoped-стиль активной ссылки через `var(--color-accent)`. Дефект W1: `aria-current` не рендерится на 4 из 5 страниц (pathname со слэшем `/work/` не совпадает с `/work`) — передано из верификации фазы 1.
- 5 страниц-заглушек с placeholder-копирайтом («Раздел в разработке — кейсы появятся в фазе 3»), без визуальной системы.
- `scripts/check-tokens.mjs` — контракт токен-дисциплины: единый файл, 5 групп, запрет hex и px-значений шкалы (4/8/16/24/32/48/64) вне tokens.css; 1–2px (outline/focus) вне шкалы — не нарушение.
- Шрифты: Manrope (body) + Unbounded (display) + JetBrains Mono (моно-слой), локальные WOFF2 с полной кириллицей, `font-display: swap`.
- UI-SPEC 01: accent с фазы 2 применяется к ссылкам и primary CTA (в фазе 1 — только активный nav + focus ring). Светлая тема — единственная (v1).
- Stacki (v0.1.3) ограничения: нет визуальной панели CSS-переменных, View Transitions — только кодовый режим; scoped styles + CSS-переменные одновременно — проверено (spike R5).
- Дизайн-направление (SPEC, precedence 0): «Calm Interface, Active Work»; визуальный язык — нейтральная светлая основа, графитовый текст, один акцент, моноширинный слой для индексов/ролей/дат/статусов, строгая модульная сетка с крупными полями, прямоугольные плоскости, тонкие линии, номера и подписи; «крупные реальные интерфейсы и схемы вместо мокапов»; «цвета проектов появляются локально и временно».

Дельта фазы: визуальных компонентов нет вообще; шкала и motion-токены — baseline; сетки и брейкпоинтов нет; интерактивных состояний нет; оболочка страниц не стилизована.

## Requirements

1. **Расширение токенов без переименования**: tokens.css дополняется bp-токенами (md, lg) и шагами шкалы (lead, caption), display масштабируется через clamp(); все значения потребляются через var().
   - Current: 5 групп токенов, шкала body/label/heading/display, motion 150/250/400ms + 1 easing; bp-группы нет
   - Target: добавлены `--bp-md` (768px) и `--bp-lg` (1200px); шаги `--text-lead` (~18px) и `--text-caption` (~12px, моно); `--text-display` — fluid через clamp(); easing-набор (2–3 кривые: standard, вхождение, выход); имена ролей не переименованы; контракт check-tokens расширен
   - Acceptance: расширенный check-tokens exit 0 (bp-группа присутствует; числа в media-запросах компонентов равны значениям bp-токенов; хардкод-значений шкалы вне tokens.css нет)

2. **Оболочка системы на 5 страницах**: index, work, lab, about, contact стилизуются оболочкой системы.
   - Current: 5 страниц-заглушек без стилизации; nav/footer голые; W1 не исправлен
   - Target: все страницы используют контейнер и gutter из токенов, типографику по шкале, стилизованные nav и структурный footer (без контента); placeholder-тексты оформлены по системе; aria-current работает на всех маршрутах (фикс W1)
   - Acceptance: build + preview отдают HTTP 200 с HTML на 5 маршрутах; в собранном HTML каждой страницы ровно один элемент с `aria-current="page"` и он соответствует маршруту; визуальный проход пользователя зафиксирован в VERIFICATION

3. **Компонентная библиотека**: базовые UI-компоненты с семантическими пропами.
   - Current: в src/components только Seo.astro; компонентов визуальной системы нет
   - Target: Button, Link, SectionHeading, ProjectCard, Media, Tag/Badge, Nav, Footer и минимальный набор инлайн-SVG иконок (контракт: сетка 24px, единый stroke, один стиль); компоненты принимают семантические пропы (layout, density, theme, showMetrics), а не сырые значения отступов
   - Acceptance: компоненты существуют в src/components и используются на страницах (grep-контроль); каждый компонент рендерится без пропов / с дефолтами без ошибки сборки; пропы layout/density мапятся на var(--space-*), не на числа

4. **Интерактивные состояния только CSS**: hover/focus/active-переходы на уточнённых motion-токенах.
   - Current: motion-токены baseline (3 длительности + 1 easing), интерактивных состояний нет
   - Target: переходы ссылок, кнопок, карточек, Tag и nav используют var(--motion-*) и var(--ease-*); easing-набор применён по назначению; при prefers-reduced-motion длительности переходов становятся 0ms во всех состояниях; клиентский JS не добавляется (порядок анимаций ADR: CSS → vanilla JS → View Transitions → island)
   - Acceptance: grep по src/components — переходы заданы только через motion/ease-токены; global.css содержит media prefers-reduced-motion (переходы 0ms); в собранных страницах 0 тегов `<script>`

5. **Контракт проектных цветов**: механизм theme-пропа с нейтральным состоянием покоя.
   - Current: механизма нет; accent с фазы 2 применяется к ссылкам и primary CTA (UI-SPEC 01); схема projects без поля цвета
   - Target: ProjectCard и Tag принимают типизированный theme-проп; на корне элемента выставляется custom property `--project-accent`; в состоянии покоя интерфейс нейтральный (SC3); поле цвета в схеме projects не добавляется (данные — фаза 3)
   - Acceptance: фикстура: компонент с theme рендерит --project-accent, без theme — нейтрален; невалидное значение theme → astro check падает (TS strict); content.config.ts не изменён

6. **Адаптивность внутри компонентов**: сетка складывается, отступы масштабируются без потери контента.
   - Current: медиа-запросов нет; адаптивности нет
   - Target: scoped-медиазапросы на bp-значениях в каждом компоненте; min-width включительно (ровно на значении bp включается следующий уровень); от 320px до 1200px+ без горизонтального скролла и потери контента
   - Acceptance: визуальный проход на 375 / 768 / 1200 зафиксирован в VERIFICATION; на 320px нет горизонтального скролла; числа медиазапросов равны bp-значениям (проверка R8)

7. **Медиа-оболочка**: Media-компонент как контракт для будущих изображений.
   - Current: медиа-компонента нет; реальных изображений нет до фазы 3
   - Target: Media (figure): соотношение сторон через aspect-ratio, рамка из токенов (1px — вне шкалы отступов), caption (моно-слой), слот для будущего `<Image>`; без изображения рендерится рамка с ratio
   - Acceptance: Media рендерится без изображения (плейсхолдер-рамка) без ошибок; содержимое слота обрезается рамкой (overflow hidden); интеграция Astro Image — фаза 3

8. **Верификация скриптами**: расширение check-tokens, контраст-чек, фикс W1.
   - Current: 6 скриптов (check-tokens с 5 группами, check-seo, check-collections, check-prohibitions, verify-preview, check-spike-doc), все с self-tests
   - Target: check-tokens расширен (bp-группа + сверка чисел медиазапросов со шкалой bp); новый check-contrast проверяет пары токенов текст/фон (перечень пар — в скрипте) на ≥4.5:1; ассерт W1 (ровно один aria-current на страницу, соответствует маршруту); grep-контроль использования компонентов
   - Acceptance: все скрипты exit 0 + self-tests зелёные; build + preview 200 на 5 маршрутах; CI (lint → check → build) зелёный

9. **Концепты первого экрана (Figma MCP)**: 2–3 варианта как референс-выбор для главной.
   - Current: макетов нет; главная — заглушка
   - Target: 2–3 варианта концепта первого экрана сгенерированы в Figma через MCP (remote-сервер, подключение на планировании фазы); выбор пользователя зафиксирован в docs/hero-concept.md; главная стилизована по выбранному варианту в рамках системы; Codex в workflow не подключается
   - Acceptance: 2–3 артефакта вариантов (ссылки/скриншоты в документе); docs/hero-concept.md с выбором и обоснованием; главная рендерит оболочку по выбору; отсутствие выбора не блокирует фазу (главная остаётся с контрактной типографикой)

## Boundaries

**In scope:**
- Расширение tokens.css: bp-токены (md/lg), шаги шкалы (lead, caption), fluid display (clamp), easing-набор — без переименования существующих ролей
- Стилизация оболочки всех 5 страниц (контейнер, gutter, типографика, nav, структурный footer, placeholder-состояния)
- Компоненты: Button, Link, SectionHeading, ProjectCard, Media, Tag/Badge, Nav, Footer + минимальный набор инлайн-SVG иконок (24px, единый stroke)
- CSS-интерактивные состояния (hover/focus/active) + prefers-reduced-motion baseline
- Контракт theme-пропа (custom property --project-accent), нейтральный покой
- Фикс W1 (aria-current на всех маршрутах)
- Медиа-оболочка (figure + ratio + рамка + caption + слот)
- Генерация 2–3 концептов первого экрана в Figma через MCP + фиксация выбора в docs/hero-concept.md
- Верификация: расширение check-tokens (bp-группа, сверка media-query), check-contrast, ассерт W1

**Out of scope:**
- Реальный контент страниц (тексты, кейсы, контакты, ссылки footer) — фаза 3
- Изображения кейсов и их обработка через Astro Image — фаза 3 (в фазе 2 — только контракт Media); превью кейсов — реальные скриншоты, не генерация
- Поле цвета в схеме projects — фаза 3 (данные проектов)
- JS-движение (scroll reveal, View Transitions, hover-preview индекса, микроинтеракции) — фаза 5 (порядок ADR: CSS → vanilla JS → View Transitions → island)
- Индекс Work с hover-preview — фаза 5
- Тёмная тема — вне v1 (UI-SPEC 01: light only)
- Utility-first CSS (Tailwind и аналоги) — запрещено ADR и P1 фазы 1
- Codex в workflow — не подключается (решение пользователя 2026-08-02)
- Скриншот-база для верификации — не выбранный контракт (скрипты + живой прогон)

## Constraints

- Единый файл токенов: новые токены живут в tokens.css; имена ролей не переименовываются (UI-SPEC 01)
- CSS media-запросы не могут потреблять var(): bp-значения заданы в tokens.css как единственный источник, числа в компонентах сверяются скриптом (R8)
- Порядок анимаций: в фазе 2 только CSS; JS-слой зарезервирован за фазой 5
- Статический SSG: клиентский JS на страницах не появляется (как фаза 1)
- Контраст текста ≥ 4.5:1 (WCAG AA) для пар токенов текст/фон, определённых в check-contrast
- Медиа-контракты для генерируемых/скачиваемых ассетов (фаза 3+): единая обработка (палитра/вуаль/рамка — системность), вторичная роль слоя (не конкурирует с контентом), лицензионная чистота (коммерческое использование), вес и оптимизация (Astro Image, LCP-бюджет §09)
- Figma MCP: remote-сервер (доступен на всех планах); подключение — на планировании фазы 2; макет после переноса — референс, не источник правды
- Контейнер 1200px (--container-max), gutter 24/48px — baseline, уточнение значений допустимо без переименования
- Stacki-совместимость: scoped styles + CSS-переменные — проверенная конструкция (spike R5); визуальной панели CSS-переменных в Stacki нет — значения токенов проверяются скриптами, не визуально
