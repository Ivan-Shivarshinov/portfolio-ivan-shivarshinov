### Д-1: Горизонтальный скролл на / при 768px (grid blowout) — исправлен

- **Обнаружен:** первый прогон `npm run verify` (2026-08-04): `FAIL / @768px
  (scrollWidth 829 <= clientWidth 768)`. Секция «Избранные работы» с 3 карточками
  (skala/buzko-legal/winwin) — 3 колонки на ≥768px; карточка-трек раздувалась до
  min-content: intrinsic-ширина скриншота 1920px (через Media/Image) давала
  карточке min-content ~279px против колонки ~245px.
- **Корень:** grid-элементы с `min-width: auto` (автоматический минимум) тируют
  трек по min-content; у карточки min-content раздувался изображением (та же
  механика, что Pitfall 3 «контент не раздувает ratio» — но по ширине).
- **Фикс (Rule 1, 03-06 Task 3):** `2b2186c` — `ProjectCard.astro`: `.card {
  min-width: 0; }` — карточка больше не раздувает трек (общий фикс: тот же паттерн
  в сетке /work, где колонки шире, но латентный риск сохранялся).
- **Верификация:** probe playwright @768px: docW 768 = clientW 768, карточки
  203px равны; полный `npm run verify` — exit 0; /work @768 в прогоне check-visual
  подтверждён через те же ширины (320/1200) + полный перепрогон без FAIL.

  не определена (она живёт только в `ensurePreview`/`spawnPreview`).
- **Фикс (Rule 1, 03-06 Task 3):** `2b2186c` — сообщение об ошибке больше не
  ссылается на `stderrRef`; stderr preview и так выводится в таймауте `ensurePreview`.
- **Следствие:** failure-path теперь корректно завершается с exit 1 и списком FAIL —
  это позволило увидеть и устранить Д-1.
