# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase 1 is scaffolding-only.** No visual styling of pages/components, no interactive behavior, no content — those are Phases 2–3. This contract fixes the token structure, baseline values, and the copy/interaction contracts that later phases build on. Values marked "baseline" are Phase 2's raw material; token NAMES and the structure are locked here (SPEC R2).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — plain CSS + CSS variables per ADR; utility-first CSS (Tailwind и аналоги) explicitly prohibited in Phase 1 (SPEC Prohibitions P1) |
| Preset | not applicable |
| Component library | none — Astro components only (layout, SEO); visual component library is Phase 2 |
| Icon library | none — no icons in Phase 1 (design SPEC §07: minimal functional signs only, from Phase 2) |

- Stacki-compatible composition is the structural contract (CONTEXT D-04): `BaseLayout` + flat list of self-closing components with props. Spike (R5) verifies CSS variables, scoped styles, JSON collections, frontmatter, View Transitions.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding, container gutter (mobile) |
| xl | 32px | Layout gaps, container gutter (desktop) |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: none — every declared value is a multiple of 4.

Token names: `--space-xs` … `--space-3xl` in `src/styles/tokens.css`. If the Stacki spike (R5) reveals a CSS-variables limitation, it is recorded in `docs/stacki-coverage.md` — the scale itself does not change.

## Typography

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Body | 16px | 400 | 1.5 | Space Grotesk (`--font-sans`) |
| Label / Meta | 14px | 400 | 1.4 (mono exception) | JetBrains Mono (`--font-mono`) — reserved for indexes, roles, dates, statuses, technical data (design SPEC §07) |
| Heading | 20px | 600 | 1.2 | Space Grotesk |
| Display | 32px | 600 | 1.2 | Space Grotesk |

- Exactly 2 weights (400 regular, 600 semibold), 4 sizes. Baseline values — Phase 2 refines the visual treatment without renaming tokens.
- Token names: `--text-body`, `--text-label`, `--text-heading`, `--text-display` (+ size/weight/line-height variables per role).
- Body line height 1.5; heading line height 1.2 (user-confirmed defaults). Label 1.4 is a declared mono-metadata exception, not an accident.
- Mono is a semantic layer, not decoration: it must not be used for body copy.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FAFAF7` | Page background, base surfaces |
| Secondary (30%) | `#F1F0EB` | Cards, nav/footer bands, secondary surfaces |
| Accent (10%) | `#A84B32` | Muted terracotta — user decision 2026-08-01 |
| Destructive | `#B3261E` | Destructive actions only — NO destructive actions in Phase 1; token reserved for later phases |
| Ink | `#1F1E1C` | Body text on dominant/secondary (graphite) |
| Ink muted | `#5C5A55` | Secondary text, captions, meta |
| On-accent | `#FFFFFF` | Text on accent fills (Phase 3+ CTA) |

Accent reserved for: **active nav state and the `:focus-visible` ring only in Phase 1**; from Phase 2+: links and the primary CTA. NOT for backgrounds, decorative fills, or "all interactive elements".

Token names: `--color-bg`, `--color-surface`, `--color-ink`, `--color-ink-muted`, `--color-accent`, `--color-accent-ink`, `--color-destructive` — all in the single `tokens.css` file. Hardcoded color values anywhere else are a SPEC R2 violation.
