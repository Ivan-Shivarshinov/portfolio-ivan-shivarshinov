# Требования: Portfolio — Иван Шиваршинов

**Defined:** 2026-07-31
**Core Value:** Портфолио подтверждает позиционирование «веб-разработчик с продуктовым подходом»: центральная интерактивная механика (индекс работ) — осмысленное доказательство компетенции, а не декоративный эффект; сайт превращает посетителя в заявку

## v1 Requirements

Требования первого релиза. Каждое отображается ровно на одну фазу roadmap. Источник: `docs/positioning_portfolio_ivan_shivarshinov.md` (PRD).

### Позиционирование

- [ ] **REQ-positioning-category**: Категория «Product-minded Web Developer» (рус.: «веб-разработчик с продуктовым подходом») — опирается на доказанную веб-разработку, объясняет растущую самостоятельность, не запирает образ внутри Webflow; без ярлыков Product Engineer, AI Product Developer, AEO/GEO Specialist, Web Systems Specialist, AI-native Developer
- [ ] **REQ-audience**: Приоритетная аудитория (технологические компании, SaaS и продуктовые команды; экспертные фирмы; B2B со сложным контентом; команды, ищущие технического партнёра; агентства и дизайнеры) и четыре ситуации клиента (запустить / привести в порядок / развивать / расширить); желаемое восприятие — самостоятельный технический партнёр по веб-направлению
- [ ] **REQ-growth-trajectory**: Траектория Product-minded Web Developer → Web Product Developer → Product Engineer; портфолио одновременно подтверждает текущую коммерческую ценность и создаёт правдоподобный мост к веб-инструментам, автоматизациям и продуктовой разработке (Lab как витрина перехода)

### Коммуникация

- [ ] **REQ-main-promise**: Основная формула обещания на первом экране: «Создаю и развиваю сложные сайты, контентные системы и веб-инструменты. Product-minded web developer. Соединяю Webflow, код, SEO/AEO и возможности ИИ…» + короткие варианты представления (рус/англ) и формулировка «от идеи и структуры до запуска и дальнейшего развития»
- [ ] **REQ-tone**: Тон коммуникации: спокойный, уверенный, конкретный, технически грамотный, без лишнего пафоса, ориентированный на результат; избегать хайпового AI-first языка, «революционных решений», лишних англицизмов, образа гения-одиночки, самоопределения через инструменты

### Компетенции и кейсы

- [ ] **REQ-competency-architecture**: Архитектура компетенций Build / Improve / Extend; иерархия коммуникации: понятный результат → доказанная специализация → коммерческое усиление → направление роста; не делать центром образа: длинный список инструментов, «делаю всё», Webflow как единственная идентичность, ИИ без конкретных внедрений, AEO/GEO как громкий ярлык
- [x] **REQ-evidence-cases**: Каждый кейс отвечает на четыре вопроса (проблема → ответственность → решение → результат) и чётко разделяет личную ответственность, вклад команды и итоговый эффект; формулировки по образцу «спроектировал CMS и мультиязычную структуру…», «исправил canonical и структуру индексации…»

### Дизайн

- [x] **REQ-design-implications**: Дизайн поддерживает образ самостоятельного, современного, системно мыслящего разработчика: содержание важнее декора, системность видна (модули, сетка, маркировка ролей/технологий/результатов), техническая глубина без перегруза, ИИ — в деталях процесса, запас для будущих кейсов; без клише «типового портфолио фрилансера» и без чрезмерно футуристического AI-стиля

## v2 Requirements

Отложено на будущий релиз. Отслеживается, но не входит в текущий roadmap.

### Lab и интерактив

- **LAB-01**: Lab Three.js-эксперимент с отдельной страницей и техническим разбором (вторичная сцена: воспроизведение механики, устройство сцены, работа AI-агента, ограничения, сравнение прототипа и production) — после устойчивой интеграции центральной механики
- **LAB-02**: Собственная переиспользуемая motion-библиотека (SceneController, ScrollProgress, ResponsiveSceneConfig, PerformanceMode, ReducedMotion, WebGLFallback, lazy loading, lifecycle management) как самостоятельный кейс
- **LAB-03**: Выразительная версия сцены для Lab (полировка: шейдер-деформации, сложные переходы между кейсами, дополнительные материалы, видео-текстуры)
- **LAB-04**: Мобильная WebGL-версия сцены (отдельная облегчённая сцена или эквивалентный канал — видео/кадры/CSS)

## Out of Scope

Явно исключено. Документировано для защиты от расползания scope.

| Feature | Reason |
|---------|--------|
| Webflow как платформа сайта | Платформа зафиксирована пользователем: Astro (static SSG + islands); Webflow — компетенция и контекст позиционирования |
| Постоянная WebGL-сцена на каждой странице | Бюджет интерактивности: одна центральная механика + один выразительный переход |
| Несколько одновременно работающих shader-эффектов | Запрещено Three.js brief |
| Навигация и критический контент внутри WebGL | HTML — главный уровень интерфейса |
| Абстрактный blob/сфера в hero без связи с работами | Запрещено Three.js brief |
| Полноэкранная 3D-галерея | Противоречит центральной механике индекса (трудно найти кейс) |
| Сетка логотипов технологий как главный визуальный аргумент | Ослабляет образ (REQ-design-implications) |
| Неоновая AI-эстетика / бесконечные градиенты как главный визуальный язык | Ослабляет образ (REQ-design-implications) |
| Тяжёлый клиентский framework для всего сайта, внешняя CMS, БД, глобальный state manager, сложный backend | Запрещено ADR (baseline стека) |
| Utility-first CSS до проверки совместимости со Stacki | ADR: обычный CSS + переменные для первого прототипа |
| Кинематографическая preload-заставка | Необязательно для запуска (design SPEC) |
| Полное повторение desktop-анимации на мобильных | Мобильная версия не обязана повторять desktop 1:1; контент и скорость важнее |
| Большое количество анимационных библиотек | Порядок: CSS → vanilla JS → View Transitions → island; GSAP/FLIP допустим только для центрального перехода |
| Документация для документации, Gantt-диаграммы, спринты | Вне модели solo-разработки |
